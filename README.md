# THE BERRY

Personal website and portfolio for **Berry Wahlberg / 花雨琦**, published at [berryuiki.github.io](https://berryuiki.github.io/).

The production site is a dependency-free static build generated by Python and deployed to GitHub Pages. The repository also retains an earlier Astro implementation as a reference for a possible future migration.

## Features

- English and Simplified Chinese desktop pages at `/en/` and `/zh/`
- A dedicated bilingual mobile experience at `/m/`
- Automatic language detection with a persistent manual override
- Light and dark themes that follow the system preference and remember the user's choice
- Full-screen hero imagery with a scroll-driven shrink effect
- Markdown-based bilingual blog
- Responsive, accessible semantic HTML
- Minified CSS and JavaScript, WebP assets, and content-hashed asset URLs

## Tech stack

The deployed site uses:

- Python standard library only (Python 3.12 in GitHub Actions)
- Handwritten HTML, CSS, and vanilla JavaScript
- GitHub Actions and GitHub Pages

No Python packages or npm dependencies are required for the production build.

> [!NOTE]
> `src/components`, `src/layouts`, `src/pages`, `src/i18n`, `astro.config.mjs`, and `package.json` belong to the earlier Astro implementation. They are not used by the current GitHub Pages workflow.

## Local development

Python 3.9 or newer is required.

```bash
python3 build_site.py
python3 -m http.server 8080 --directory dist
```

Then open [http://localhost:8080](http://localhost:8080).

The build writes the generated site to `dist/`. This directory is ignored by Git.

## Updating the site

### Portfolio copy

Edit the `T` translation dictionary near the top of `build_site.py`. Keep the `en` and `zh` entries structurally aligned.

### Blog posts

Add Markdown files to `src/content/posts/`. Each file must start with front matter in this format:

```markdown
---
title: 'Post title'
date: 2026-08-28
lang: 'en'
description: 'A short summary for metadata.'
---
```

Use `lang: 'en'` or `lang: 'zh'`. Translated versions are separate files and may use different slugs.

The built-in Markdown renderer supports second-level headings, paragraphs, unordered lists, blockquotes, fenced code blocks, bold text, emphasis, inline code, and external links.

### Styles and images

- Edit `src/styles/global.css` for desktop styles.
- Edit `src/styles/mobile.css` for the dedicated mobile page.
- Place source images in `src/assets/`.
- Provide WebP versions for production; the build copies only `.webp` image assets to `dist/`.

### Base path

The site is configured for a GitHub user page at the domain root. `BASE` in `build_site.py` is therefore an empty string. Update it if the site is moved to a project subpath.

## Deployment

Every push to `main` triggers `.github/workflows/deploy.yml`, which:

1. checks out the repository;
2. sets up Python 3.12;
3. runs `python build_site.py`;
4. uploads `dist/` as the GitHub Pages artifact; and
5. deploys the artifact to GitHub Pages.

The workflow can also be started manually from the GitHub Actions tab.
